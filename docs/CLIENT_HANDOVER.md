## Supported production deployment

Use Node.js 24.7+ with persistent filesystem storage. The included `render.yaml` provisions a persistent disk and configures:

- `FLEXER_DATA_DIR=/var/data/flexer/database`
- `FLEXER_UPLOADS_DIR=/var/data/flexer/uploads`

The merchant must set `DEFAULT_ADMIN_PASSWORD`. `JWT_SECRET` is generated by the Render Blueprint. For another Node host, configure both secrets and both persistent paths explicitly.

Do not use Netlify/Vercel functions, a static Drop, or FTP-only hosting for production orders. Those environments do not provide the durable SQLite and upload storage this application requires. The obsolete PHP bridge is intentionally blocked.

## Required merchant approvals before launch

The client must verify or replace the remaining business-owned values listed in `docs/CONTENT_TODO.md`, especially:

- bank account and transfer instructions;
- WhatsApp/community links;
- final catalogue names, prices, stock, specifications, and product photography;
- delivery, returns, warranty, privacy, and terms copy;
- the production domain and analytics preferences.

Koko remains disabled until FLEXER supplies approved merchant credentials and the provider adapter is implemented and tested against Koko's official sandbox.

## Data handling before sharing source

`data/flexer.db` is the existing local merchant database and contains historical/test order and subscriber records. Do not include it in a third-party source handoff unless the data owner has approved that disclosure. Fresh persistent deployments seed a clean catalogue database from code and do not copy this local file.
